# 壹页

一个零构建的静态导航页，参考 Apple 官网的视觉语言：大留白、克制的灰阶、毛玻璃导航、有物理感的动效。

- **搜索**：匹配名称、描述、网址、域名、**别名 tags**，命中关键词会高亮
- **分类筛选**：顶部 chip 统一承担切换与定位（不再与导航重复列一遍）；状态写入 URL hash 可直接分享；切换时用 FLIP 让卡片平滑移动而非瞬跳
- **深浅色主题**：首访跟随系统，手动切换后记住；切换时图标旋转淡入
- **动效**：Hero 极光视差、滚动揭示、卡片交错上映、指针跟随柔光、回到顶部环形进度、统计数字滚动
- **收藏置顶**：卡片右上角点星标，收藏的站点自动汇总到顶部「常用」区
- **键盘导航**：`/` 搜索 → `↓` 进入结果 → 方向键移动 → `Enter` 打开，全程无需鼠标
- **视图切换**：网格 / 紧凑列表，一屏看更多
- **批量导入**：粘贴多行文本一次加一批站点
- **站内编辑**：新增/修改/删除站点与分类、拖拽排序（触屏可用上下移按钮）
- **一键提交 GitHub**：连接后本机改动可直接提交到仓库，所有设备同步（两种连接方式，见下）
- **零依赖**：无框架、无构建、无统计；仅可选的 GitHub 提交涉及一个外部服务

## 文件结构

```
links/
├── index.html    # 页面本体（HTML + CSS + JS 全内联）
├── links.json    # 你的网址数据，唯一需要维护的文件
├── favicon.svg   # 站点图标
├── .nojekyll     # 让 GitHub Pages 跳过 Jekyll 处理
├── worker/       # 可选的 OAuth 中转服务（仅方式二需要部署）
│   ├── worker.js
│   ├── wrangler.toml
│   └── README.md
└── README.md
```

## 本地预览

`links.json` 是通过 `fetch` 读取的，**直接双击 `index.html` 会被浏览器的 CORS 策略拦住**，必须起一个本地服务器：

```bash
cd links
python3 -m http.server 8000
# 打开 http://localhost:8000
```

改了 `links.json` 后刷新浏览器即可（已设 `cache: no-cache`，不会读到旧数据）。

## 收藏与个性化

卡片右上角的星标（悬停显现，已收藏时常亮）用于收藏，收藏项会自动汇总到页面顶部的「常用」区。

个性化设置（收藏、最近访问、视图模式）存在浏览器 `localStorage`：

- **收藏**：导出 `links.json` 时会一并写入 `starred` 字段，换设备后导入即恢复
- **最近访问**：点击站点时记录，用于排序参考
- **视图模式**：网格 / 紧凑列表

## 站内编辑

点右上角「编辑」进入编辑模式，可以直接：

- **新增站点**：右下角悬浮「添加站点」按钮（先选分类），或分类标题右侧的「添加」
- **批量导入**：分类标题右侧的「批量」，粘贴多行文本一次加一批
- **修改/删除**：每张卡片右侧的铅笔与垃圾桶图标（编辑态下点卡片本身也可编辑）
- **排序**：鼠标可拖拽卡片调整顺序、可跨分类拖；拖分类标题左侧手柄调整分类顺序。
  触屏上 HTML5 拖拽不可靠，因此每张卡片另有上/下移按钮
- **管理分类**：分类标题右侧「重命名」「删除」
- **校验**：名称必填；网址必须以 `http://` 或 `https://` 开头，不合法会拦下并标红

批量导入的格式（每行一个，`#` 开头的行会被忽略）：

```
GitHub | https://github.com | 代码托管
https://example.com
MDN | https://developer.mozilla.org
```

### 改动先存在本机，再选择如何持久化

编辑的内容先写入浏览器 `localStorage`，**本机立即生效、刷新仍在**。之后有三种去向：

| 方式 | 操作 | 特点 |
| --- | --- | --- |
| **提交到 GitHub** | 连接 GitHub 后点「提交到 GitHub」 | 一个按钮写回仓库，**所有设备可见**（推荐） |
| 导出文件 | 点「导出」下载 `links.json`，替换仓库文件并提交 | 无需任何授权，但手工 |
| 留在本机 | 什么都不做 | 仅这台设备可见 |

页面顶部在检测到本机改动时会显示提示条，三个入口都在那里。

提交走 GitHub Contents API，带 `sha` 乐观锁：若线上文件在你的编辑期间被别处改过，提交会被拒绝并询问是否覆盖，**不会静默丢改动**。

### 不想用站内编辑？

直接在 GitHub 网页打开 `links.json`，点铅笔图标改完 Commit 即可，Pages 一分钟内自动更新 —— 零开发成本，缺点是手写 JSON、手机上不方便。

## 连接到 GitHub

点右上角「连接 GitHub」，两种方式任选：

### 方式一 · 粘贴 Personal Access Token（零成本，推荐个人使用）

无需部署任何服务。

1. 打开 GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token
2. **Repository access** 只勾选本仓库
3. **Permissions** → Repository permissions → **Contents: Read and write**
4. 生成后粘贴到连接弹窗

> ⚠️ **务必用 fine-grained token 并把权限锁到本仓库**。Classic token 的 `public_repo` 权限覆盖你**所有**公开仓库，一旦泄露影响面大得多。
>
> token 保存在浏览器 `localStorage`。任何能读取该页面 storage 的东西（恶意浏览器扩展、XSS 漏洞）都可能拿到它。因此：权限务必最小化，不再使用时立刻断开连接并到 GitHub 吊销 token。

### 方式二 · GitHub OAuth 登录（体验更好，需要部署一个小服务）

点一下登录即可，无需手工管理 token。但因为 **GitHub 的换 token 接口不支持浏览器跨域**，且 `client_secret` 绝不能放在前端，所以需要一个极小的中转服务来完成 "code → token" 交换。

好消息是：**提交文件本身完全在浏览器里完成**（已实测 GitHub Contents API 支持跨域），所以这个中转服务无状态、不接触仓库、不存任何数据。

完整实现与部署文档在 [`worker/`](worker/README.md)，包含：

- 在 GitHub 创建 OAuth App 的每一步
- 获取自己的 GitHub 数值 ID
- 用 wrangler 部署到 Cloudflare Workers（免费额度足够）
- 自测方法与常见故障排查

部署完成后，把得到的两个值填进 `links.json`：

```json
{
  "auth": {
    "clientId": "你的 OAuth App Client ID",
    "workerUrl": "https://你的worker.workers.dev"
  },
  "repo": { "owner": "BorisXiao", "name": "links", "branch": "main", "path": "links.json" }
}
```

`repo` 字段决定提交目标，仓库改名后改这里即可，不用动代码。

### 两种方式对比

| | Token | OAuth |
| --- | --- | --- |
| 需要部署服务 | 否 | 是（一个 Worker） |
| 需要长期维护 | 否 | 是（Worker + OAuth App） |
| 登录体验 | 手工粘贴一次 | 点一下 |
| 安全性 | 取决于 token 权限范围 | 服务端会校验只有你本人可用 |
| 故障点 | 1 个 | 3 个 |

对个人书签页，**建议先用 Token**；确实觉得麻烦再升级到 OAuth —— 前端的提交流程两者共用，升级不会白做。

## 维护网址

只需要编辑 `links.json`：

```json
{
  "title": "常用网址",
  "subtitle": "把每天要打开的站点放在一处",
  "categories": [
    {
      "name": "开发工具",
      "links": [
        { "name": "GitHub", "url": "https://github.com", "desc": "代码托管与协作" }
      ]
    }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 否 | 页面大标题与浏览器标题；省略则保留默认 |
| `subtitle` | 否 | 标题下方一句话；省略则不显示 |
| `categories[].name` | 是 | 分组名，同时用作导航锚点和筛选按钮 |
| `categories[].icon` | 否 | 预留字段，当前未使用 |
| `links[].name` | 是 | 站点名 |
| `links[].url` | 是 | 网址，必须带 `https://` |
| `links[].desc` | 否 | 一句话描述；省略则显示域名 |
| `links[].tags` | 否 | 别名数组，用于搜索。例如 YouTube 配 `["油管"]`，搜「油管」也能命中 |
| `links[].icon` | 否 | 官方图标路径（如 `/favicon.ico`），会拼在 `url` 之后。用于聚合服务取不到图标的站点 |

- 分类顺序 = 页面展示顺序
- 某分类 `links` 为空数组则整组不渲染
- 别名只参与搜索，不显示在页面上 —— 想让站点用你的习惯叫法搜到就加 `tags`

当前编目（73 个站点 / 7 个分类，按使用频次排序）：

| 顺序 | 分类 | 数量 | 说明 |
| --- | --- | --- | --- |
| 1 | 常读 | 15 | LINUX DO、V2EX、Hacker News、掘金、博客园、酷壳、阮一峰、Google/百度/维基 |
| 2 | 开发工具 | 15 | GitHub、MDN、Stack Overflow、npm、PyPI、Docker Hub、Vercel 等 |
| 3 | AI 工具 | 16 | DeepSeek、ChatGPT、Claude、Gemini、Grok、Hugging Face、Ollama 等 |
| 4 | 社交 | 11 | X、Facebook、Instagram、Threads、Reddit、TikTok、小红书、微博、Telegram、Discord、LinkedIn |
| 5 | AI 状态 | 3 | TIBO（Codex 重置动态）、OpenAI Status、Claude Status |
| 6 | 影音 | 5 | YouTube、哔哩哔哩、Netflix、Spotify、Twitch |
| 7 | 效率 | 8 | Excalidraw、Carbon、TinyPNG、Squoosh、PDF24、草料、ITDOG、Speedtest |
- **别删掉 JSON 的引号和逗号**，格式错误会导致页面显示「数据加载失败」

## 部署到 GitHub Pages

```bash
git add links.json
git commit -m "chore: 更新网址"
git push
```

Pages 会在约 1 分钟内自动重新发布。

### 首次部署设置

仓库 **Settings → Pages**：

- **Source** 选 `Deploy from a branch`
- **Branch** 选 `main`，目录选 `/ (root)`
- 保存，等 1–2 分钟

访问 `https://<用户名>.github.io/<仓库名>/`。

## 设计说明

### 版面结构

一页内只用一个对齐轴 —— 标题、描述、统计、分组标题、卡片全部左对齐。

早期版本是「Hero 居中 + 内容左对齐」，两条对齐轴打架，版面会显得散。Apple 的页面几乎从不在同一列里混用居中与左对齐，所以改为统一的左对齐编辑式布局，并为每组数据加了语义化的竖线分隔。

分类切换只保留一处入口：顶部 chip 一排在滚动时吸顶，同时承担筛选与定位，不再由导航栏重复列一遍。

### URL 约定

| 形式 | 含义 |
| --- | --- |
| `#cat=影音` | 筛选到某分类，可分享 |
| `#sec=影音` | 滚动定位到某分组 |
| 无 hash | 显示全部 |

两种语义用显式前缀区分（早期版本共用一个裸分类名，导致 `#c-AI 状态` 解析后匹配不到任何分类而显示空白页）。旧的 `#c-分类名` 写法仍兼容，无法识别的 hash 一律安全回退到「全部」，不会出现空白页。

### 为什么暗色不用纯黑

纯黑背景（`#000`）上放近黑卡片（`#1c1c1e`），两者亮度差仅 **1.23:1**，卡片会失去依附感、看起来像一个个"黑框"。改用分层灰阶后：

| 层级 | 亮色 | 暗色 |
| --- | --- | --- |
| 页面底色 | `#f5f5f7` | `#0b0b0d` |
| 卡片 | `#ffffff` | `#17171b` |
| 悬停 | `#ffffff` | `#1e1e23` |

再配合可见描边（亮色 `rgba(0,0,0,.07)` / 暗色 `rgba(255,255,255,.085)`）建立层次。

### 文字对比度（WCAG AA 需 ≥ 4.5:1）

| 用途 | 亮色 | 暗色 |
| --- | --- | --- |
| 站点名 | 16.8:1 | 16.2:1 |
| 描述文字 | 6.3:1 | 7.5:1 |

### 图标为什么用浅底 + 投影

绝大多数品牌 logo 是深色或彩色，放在暗底上会糊成一团 —— 这是最初"黑框"观感的主因，所以头像恒定用浅底（`#f2f2f4`），两种主题一致。

但极少数 logo 是**纯白**的（如 Reddit），贴浅底会隐形（对比仅 1.12:1）。因此给图标加了一圈极淡投影勾出边界，白色 logo 靠阴影显形，深色与彩色 logo 不受影响 —— 比换成土气的中灰底更优雅。

### 图标级联回退

```
links.json 的 icon 字段（官方图标，品牌保真）
   ↓ 失败
favicon 聚合服务（可绕过部分站的防盗链与网络限制）
   ↓ 失败
名称首字母色块（离线可用，永不空框）
```

实测两者各有不可替代之处：**LINUX DO 直连返回 403 但聚合服务可取；小红书恰好相反**，所以级联而非二选一。另会主动检测"返回空白图但不报错"的情况。

## 技术说明

| 项目 | 说明 |
| --- | --- |
| 图标来源 | 通过 Google favicon 服务按域名获取；**取不到时自动降级为名称首字母色块**，不依赖网络也能看清 |
| 已知现象 | 极少数站点（如 `crates.io`）Google 服务抓不到图标会返回 404，控制台可能有一条外部资源报错。不影响显示，会走色块降级 |
| 权限边界 | 站点自身资源零 404；无任何第三方脚本，唯一的跨域请求是 favicon 图片 |
| 无障碍 | 键盘可达、搜索框 `aria-label`、筛选按钮 `aria-pressed`、`prefers-reduced-motion` 下关闭全部动效 |
| 兜底保护 | 滚动揭示若未按预期触发，1.2s 后强制显示所有分组 —— 宁可牺牲动画，也绝不让内容不可见 |
| 响应式 | 移动端单列、导航锚点自动折叠、搜索框占满宽度 |
| 兼容性 | 使用 `backdrop-filter`、`color-mix`、`IntersectionObserver`、CSS 自定义属性，支持 2020 年后的现代浏览器 |
